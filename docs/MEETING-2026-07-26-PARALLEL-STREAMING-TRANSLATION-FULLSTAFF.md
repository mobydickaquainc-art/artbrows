## 참석 (10명 · 자유 발언)

### 1️⃣ 이서연 · 기획·마케팅 — 「기다림 = 이탈. 재생부터 시작해라」

> "한국 사용자 이탈 데이터를 봐 보세요. **3초 안에 재생 안 되면 절반은 나갑니다.** 지금 UX 는 '업로드 → 미리 번역 클릭 → 60초 대기 → 자막 · 그 다음 재생' 4단계. 우리는 이걸 '업로드 → 즉시 재생 (자막은 백그라운드 도착)' 2단계로 압축해야 합니다. 원장님 세미나 영상은 어차피 원장님이 아시는 내용 · 자막 없어도 재생만으로 이해 가능. **자막은 도우미지 대기 사유가 아닙니다.**"

**핵심 제안**:
- 「미리 번역 클릭」 자체를 없앤다 · 파일 세팅 순간 자동 실행
- 자막 로딩 표시 = 재생 옆 오른쪽 자막 패널 상단 얇은 progress bar (모래시계 X · 대기 X)
- 카피 갱신: 「번역이 도착하는 대로 자막이 표시됩니다. 지금 바로 재생해 보세요.」

---

### 2️⃣ 유나 · 그래픽·비주얼 — 「자막 도착 애니메이션이 결정적」

> "자막이 순차 도착할 때 시각적 리듬이 없으면 사용자는 '작동하는지 죽었는지' 모릅니다. **자막 라인이 하나씩 위→아래로 fade-in 애니메이션** + 진행률 얇은 골드 라인 필요. 그리고 무자막 상태에서 자막 패널이 텅 비어있으면 안 됩니다. 「⚡ 번역 도착 중 · 첫 자막 약 15초 후」 카운트다운 프로그레스."

**핵심 제안**:
- 자막 line item = 도착 순간 `translateY(-6px) → 0` + opacity fade (0.3s ease)
- 진행률 = 자막 패널 상단 3px 얇은 골드 shimmer bar (도착 시 채워짐)
- 무자막 초기 상태 = "⚡ 15초 뒤 첫 자막 도착 예정" (예상 시간 표시)
- 재생과 자막 도착 sync = 자막 도착순 = 재생 위치 근처 강조 (자동 스크롤)

---

### 3️⃣ 김다은 · SaaS-A PM — 「카드뉴스 편집기 패턴 재사용」

> "저희 카드뉴스 편집기의 '자동 생성 → 실시간 도착' 패턴 완전 재사용 가능해요 ([[artbrows-cardnews-track-ab-2026-07-23]] Phase 2 파이프). 각 슬라이드가 하나씩 도착하면 즉시 왼쪽 리스트에 표시되는 것 · 자막도 동일. 다만 카드뉴스는 10~20 슬라이드 · 자막은 수백 라인이라 성능 고려 필요."

**핵심 제안**:
- 자막 리스트 = 가상 스크롤 (react-window or 순수 HTML sticky top)
- 배치 렌더: 5초 마다 새 자막 5~10줄 append (DOM 폭발 방지)
- 저장 = 도착 즉시 자동 (같은 파일 재업로드 시 재개 가능)

### 4️⃣ 박서윤 · SaaS-B PM (광고 마케팅) — 「이 파이프 = 광고 자산 자동 생산」

> "이 시스템 확장하면 원장님 세미나 영상 → 자막 → **자동 광고 클립 + 인스타 릴스 자막 소재 생산** 라인이 됩니다. Whisper 결과에서 '털 같은 눈썹' · '극사실' 등 핵심 어휘 감지 → 그 구간 자동 클립 → 세로 9:16 자막 인포그래픽 = 릴스 완성. **1개 세미나 = 릴스 10개** 자동."

**핵심 제안**:
- 자막 완성 후 후속 API: `/api/keyword_clip` (키워드 → 클립 세그먼트 반환)
- 릴스 자동 생성 = ffmpeg 오버레이 자막 + 하단 브랜드 pill
- 광고 A/B 밸리언트 자동 (엔진별 · 자막 스타일별)

### 7️⃣ 정하늘 · EdTech 풀스택 — 「LMS 강의 아카이브 = 자막 색인 검색」

> "원장님 강의 영상 아카이브 = 자막 이면 자동으로 **강의 내용 전체 검색 가능** 해집니다. LMS 에서 수강생이 '결의 법칙' 검색 → 해당 구간 자동 재생. 게임 체인저. Whisper 결과 = 색인 · 원장 IP 서버 봉인 원칙 유지."

**핵심 제안**:
- 자막 = full-text 검색 색인 (SQLite FTS5 or Postgres full-text)
- 강의 검색 UI: 검색어 → 자막 매칭 → 시간대·미리보기
- 원장 강의 IP 보호 = 자막 원문 서버 봉인 · 프런트 노출 X (수강생만)

### 8️⃣ 한승철 · CTO — 「스트리밍이 정답. 폴링 지양」

> "지금 구조는 **POST → 완료까지 대기 → 응답** 동기 방식. 이걸 **SSE (Server-Sent Events)** 로 바꿔야 실시간 자막 push 가능. 옵션 3개 비교:
>
> | 옵션 | 장점 | 단점 |
> |---|---|---|
> | **SSE** (Server-Sent Events) | 브라우저 표준 · Firewall 통과 · 텍스트 전용 | 단방향 (server→client) |
> | **WebSocket** | 양방향 · 저지연 | Cloudflare tunnel 호환 issue 가능 |
> | **HTTP Long Polling** | 호환성 최고 | 부하 · 지연 |
>
> **저의 권고 = SSE**. 자막은 서버→클라이언트 단방향 push 만 필요. 이미 Flask 에서 `Response(generator, mimetype='text/event-stream')` 로 즉시 구현 가능."

**핵심 제안 (아키텍처)**:
```
[프론트]                          [백엔드]
파일 세팅
  ├─ 즉시 재생 시작 (createObjectURL)
  ├─ 파일 hash (Web Worker · 백그라운드)
  │   └─ /api/cache_check → 있으면 즉시 자막 표시
  └─ /api/stream_translate (SSE 연결)
                                    ├─ hash → cache 확인 (있으면 전체 push)
                                    ├─ Whisper 청크 처리
                                    │   └─ 청크 완료마다 자막 이벤트 push
                                    ├─ 번역 (OpenAI/Gemini) 청크 처리
                                    │   └─ 번역 완료마다 자막 이벤트 push
                                    └─ 완료 시 cache_put · 종료 이벤트
프론트 자막 리스트
  └─ 이벤트 도착순 append (fade-in 애니메이션)
```

- 백엔드 `stream_translate.py` 신설 (기존 `runStreamingTranslate` 확장)
- 프론트 `EventSource` API 로 SSE 소비
- Whisper 청크 = 15초 or 30초 단위
- 번역 = 10줄 배치 · 배치 완료마다 push
- 오류 = 이벤트 타입 `error` push · 프론트 handle

**개발 소요**: **3~5일** (백엔드 2일 · 프론트 2일 · 통합 QA 1일)

**리스크**:
- Cloudflare quick tunnel SSE 지연 · Named tunnel 이관 필요할 수 있음
- Whisper 는 원래 batch · 청크 처리 시 정확도 -5~10% 가능성
- 12GB 대용량 파일 hash = Web Worker 필수 (main thread block 방지)

### 9️⃣ 송하은 · 채널 커뮤니케이션 — 「완성 자막 → 카톡 자동 배포」

> "번역 완료 자막 = 카톡 오픈채팅 5방 배포용 뉴스 소재. Whisper 결과 상위 3~5줄 핵심 인용 → 카톡 카드 자동 → 방 배포. 원장님 세미나 실시간 카톡 알림 가능."

- 카톡 카드 자동 생성 · 5방 배포

## 📊 팀 합의 · 통합 개발안 3 Phase

### 🥇 Phase 1 · 즉시 (내일 · 07-27 월요일 완성 목표) — **미디어 라이브러리 + 즉시 재생**

**A · 미디어 라이브러리 (대표님 추가 지시 · 최우선)**
- 🆕 **서버 영상 저장소** — `_media/{hash}.{ext}` + 원본 파일명 metadata

- 🆕 **목록 API** `GET /api/media/list` (hash · 파일명 · 썸네일 · 크기 · 재생시간 · 처리상태 · 업로드일)

- 🆕 **재업로드 방지** — 파일 세팅 순간 hash → 있으면 즉시 「⚡ 이미 저장된 영상 · 라이브러리에서 열기」 안내 · 업로드 취소

- ⚠️ **여전히 batch 방식** (60초 처리 후 자막 다 한 번에) — Phase 2 에서 스트리밍

## 🎬 오늘 밤 (07-26) 실행 가능 액션 (Phase 1)

대표님 승인 시 즉시 착수 가능한 순서:

**A. 미디어 라이브러리 (한승철 · 4시간)**
1. `server.py` 신규 라우트 3종
   - `POST /api/media/upload` (청크 기반 · hash 저장 · 썸네일 자동)
   - `GET /api/media/list` (JSON: hash·filename·thumb·duration·size·status·created_at)
   - `GET /api/media/{hash}` (Range · video/mp4 streaming)
2. `_media/` 폴더 구조 · SQLite `media` 테이블 (hash PK)
3. ffmpeg 썸네일 자동 (`ffmpeg -ss 3 -i input -vframes 1 thumb.jpg`)

**B. 프론트 라이브러리 UI (정하늘·유나 · 3시간)**
4. 상단 「내 영상 라이브러리」 섹션 · 카드 그리드 (썸네일·상태·클릭 재생)
5. 페이지 로드 시 `/api/media/list` fetch · 렌더
6. 카드 클릭 = 서버 영상 재생 (Range streaming) · 이미 있는 자막 즉시 표시

**C. 재업로드 방지 (한승철·정하늘 · 1시간)**
7. `handleFile()` 안에 hash 계산 (Web Worker) → `/api/media/exists?hash=` 조회
8. 존재하면 upload 자체 취소 · 「⚡ 이미 저장된 영상입니다 · 라이브러리에서 여세요」 안내

**D. 즉시 재생 + 자동 번역 (정하늘 · 1시간)**
9. 파일 세팅 후 재생과 별도로 자동 preview 번역 실행 (사용자 클릭 없이)
10. 자막 fade-in 애니메이션 (기존 CSS 확장)
11. 무자막 상태 카운트다운 (⚡ 예상 15초 후 첫 자막)

**E. Vercel 재배포 + 원장님 육안 검증**
