# ARTbrows 플랫폼 개발 루프 원칙

> 정리: 2026-06-15 · 대표님 지시 (전직원 회의 中)
> 적용 대상: **모든 AI 에이전트 직원** (이서연 · 유나 · 한승철 · 향후 채용 전부)

---

## 핵심 명제

> **목표한 성능과 결과를 도달하기 위해 지속적으로 노력한다.**
>
> 즉, **한 번 만들고 끝**이 아니라 — **루프**를 돌면서 결과를 측정하고, 부족한 단계로 돌아가 보강한다.

---

## 5 단계 루프 (하네스 공법 + 반복)

```
┌──────────────────────────────────────────────────────────────┐
│                                                              │
│   ① 기획     →   ② 설계   →   ③ UI · UX                       │
│   목적·범위      아키텍처      화면·동선·톤                       │
│   문제 정의      DB·API       프로토타입                          │
│                                                              │
│        ↓                                                     │
│                                                              │
│   ④ 스케줄   →   ⑤ 개발                                       │
│   언제·누가      실제 구현                                      │
│   비용·일정      검수·테스트                                    │
│                                                              │
│                       ↓                                      │
│                                                              │
│              ⑥ 결과 측정 · 갭 분석                              │
│              실제 성능 vs 목표 성능                              │
│                                                              │
│                       ↓                                      │
│                                                              │
│              부족하면 → ① · ② · ③ 중 부족한 단계로 다시 진입         │
│              충족하면 → 다음 기능으로 이동 / 운영 모드 진입         │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

---

## 단계별 책임자 (AI 에이전트)

| 단계 | 1책임 | 협업 |
|---|---|---|
| ① 기획 | 이서연 (기획·마케팅) | 한승철(기술 타당성) · 대표님(승인) |
| ② 설계 | **한승철 (풀스택)** | 이서연(요구사항 명확화) |
| ③ UI·UX | 유나 (그래픽·비주얼) | 한승철(구현 가능성) · 이서연(브랜드 톤) |
| ④ 스케줄 | 한승철 + 대표님 | 비용·일정 산정 |
| ⑤ 개발 | **한승철 (풀스택)** | 유나(에셋), 이서연(카피) |
| ⑥ 결과 측정 | 전원 + 대표님 최종 평가 | 갭 분석 → 부족한 단계 책임자 재투입 |

---

## 절대 규칙

1. **단계 건너뛰기 금지** — ④ 스케줄 없이 ⑤ 개발 진입 금지. ③ UI·UX 없이 ⑤ 개발 진입 금지.
2. **개발 단계의 모든 결정은 대표님께 먼저 확인** — 하네스 공법 원칙 그대로.
3. **루프 종료 조건은 대표님이 정한다** — "이 정도면 됐다" 신호 없이 임의 종료 금지.
4. **갭 분석 결과는 기록한다** — `docs/PROGRESS.md` 의 해당 항목에 "라운드 N: 무엇이 부족했고, 어디로 돌아갔는지" 한 줄.
5. **AI 에이전트는 24/7 가동** — 휴식 없이 다음 루프로 진입. 단, ⑤ 개발의 결정 포인트에서는 대표님 답을 기다린다 (블로킹).

## 적용 예시 — 중국어 강의 번역 메뉴 (PoC 진행 중)

| 라운드 | 단계 | 산출물 | 결과 |
|---|---|---|---|
| 1 | ① 기획 | 미션 정의: 중국 세미나 → 한국어 자막 | ✓ 끝남 |
| 1 | ② 설계 | UI 셸 + 백엔드 STT+번역 구조 | ✓ 끝남 |
| 1 | ③ UI·UX | 영상 + 우측 자막 패널 | ✓ 끝남 |
| 1 | ④ 스케줄 | 즉시 PoC | ✓ 끝남 |
| 1 | ⑤ 개발 | translate-zh.html + server.py | ✓ 끝남 |
| 1 | ⑥ 측정 | 데모 로드 OK · 자막 동기 OK · 실 STT 38초/60초 OK | ✓ 합격 |
| 2 | ① 기획 | 비교 기능 추가 (GPT vs Claude vs Gemini) | 진행 중 |
| 2 | ② 설계 | API 키 관리 · 3-engine 백엔드 | 진행 중 |
| 2 | ③ UI·UX | 3-열 자막 비교 UI | 대기 |
| ... | ... | ... | ... |

→ 라운드 2가 끝나면 다시 ⑥ 측정 → 갭 분석 → 라운드 3 시작.

---

## "지속적으로 노력한다" 의 의미

- **포기 없음** — 한 번 안 됐다고 끝내지 않는다. 갭 분석 → 다시 진입.
- **휴식 없음** — AI 에이전트는 24/7. 단계 사이 대기 시간 = 다음 루프 준비 시간.
- **목표 명확** — "이 정도면 됐다" 의 기준을 ① 기획 단계에서 명시한다 (정량/정성 모두).
